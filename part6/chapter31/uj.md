# Clean Architecture 6부 31장 정리: 웹은 세부사항이다

GUI는 세부사항.
웹은 GUI를 구현하는 하나의 방식. 웹도 세부사항.

과거에는 서버에서 HTML을 만들어 전달했지만, 자바스크립트가 등장하면서 브라우저에서도 많은 로직과 처리가 가능해짐.

하지만 웹 기술이 어떻게 변하든 **UI와 APP 사이에는 추상화 가능한 또 다른 경계가 존재**.

APP의 핵심 업무 규칙이 웹이나 브라우저에 직접 의존할 필요는 없음.

- 웹 : 데이터를 입력받고 보여주는 전달 메커니즘
- APP : 실제 업무 규칙과 유스케이스를 수행

즉, React, 브라우저, HTML, JavaScript 같은 웹 기술이 바뀌더라도 핵심 APP 로직까지 같이 바뀌어서는 안 됨.

**웹은 시스템의 중심이 아니라 입출력 장치에 가까움.**

웹도 중요함.
UI도 중요함.
하지만 아키텍처 관점에서 웹은 세부사항.

---

### Q. 그럼 작가에 의하면 프론트엔드는 세부사항만 다루는 직군이라는 건가?

**A.** 놉.

**프론트엔드가 사용하는 기술 중 많은 것들이 아키텍처 관점에서 세부사항**.

여기서 세부사항은 중요하지 않다는 의미가 아니라 **교체 가능한 기술적 선택**이라는 의미에 가깝다고 봄.

예를 들면

- React
- Vue
- DOM
- 브라우저
- HTTP

같은 것들은 세부사항.

하지만 프론트엔드에서 다루는 모든 로직이 세부사항은 아니니까..

예를 들어 Todo APP에서

> 완료된 Todo는 캘린더에 표시하지 않는다.

이건 APP의 규칙. 유스케이스나 업무 규칙에 가까움.

반면

> Todo 데이터를 FullCalendar의 Event 형식으로 변환한다.

이건 외부 라이브러리와 APP 사이를 연결하는 Adapter에 가까움.

> React의 useEffect에서 Axios를 이용해 데이터를 요청한다.

이건 구현 세부사항.

즉, 같은 프론트엔드 코드 안에서도 계층이 나뉠 수 있음.

Todo 완료 여부 판단
→ Application / Business Rule

Todo → Calendar Event 변환
→ Adapter

React / FullCalendar / Axios
→ Detail

따라서 **"프론트엔드는 세부사항이다"가 아님**.

**웹이라는 기술을 시스템의 아키텍처 중심에 놓지 마라.**

React로 개발한다고 React를 중심으로 시스템을 설계하는 게 아니라, APP의 규칙을 먼저 만들고 React는 이를 사용자에게 전달하는 수단으로 사용해야 한다는 얘기인듯.
