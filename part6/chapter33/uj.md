# Clean Architecture 6부 33장 정리 : 사례 연구 - 비디오 판매

지금까지 배운 Clean Architecture 원칙을 실제 APP 설계에 적용한 사례.

먼저 기술이 아니라 **유스케이스와 액터를 분석**.

같은 기능처럼 보여도 액터가 다르면 변경 이유가 다를 수 있기 때문에 SRP에 따라 분리.

유스케이스를 기준으로 컴포넌트의 경계를 나누고, 의존성은 핵심 업무 규칙을 향하도록 설계.

필요한 경우 DIP와 인터페이스를 이용해 의존성 방향을 역전.

결국,

**유스케이스 분석 → 액터와 변경 이유 파악 → 컴포넌트 분리 → 의존성 관리**

지금까지 배운 원칙을 실제 설계에 적용한 예시.
