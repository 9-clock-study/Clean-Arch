# Clean Architecture 6부 30장 정리: 세부사항

DB는 세부사항.

DB가 중요하게 여겨진 이유는 사실상 **'디스크' 때문**.
디스크는 데이터 접근 속도가 느리기 때문에 이를 효율적으로 사용하기 위한 여러 기술이 필요해짐.

- 색인(Index)
- 캐시(Cache)
- 쿼리 계획 최적화
- 데이터 표현 및 저장 방식

즉, DB는 **데이터를 디스크에 체계적으로 저장하고 각 시스템에 적합한 방식으로 접근하기 위한 기술**.

대표적인 데이터 접근 방식

- 파일시스템(문서 기반) : 파일명, 경로 등을 통해 문서 단위로 접근
- RDBMS : 테이블과 관계를 기반으로 구조화된 데이터에 접근. 비정형 문서 처리에는 상대적으로 부적합

반면 메모리에서는 연결 리스트, 트리, 해시테이블, 스택, 큐 등의 데이터 구조를 사용하고, 참조나 포인터를 통해 데이터에 접근.

DB의 색인이나 쿼리 최적화처럼 **성능을 위한 데이터 접근 방식도 중요함**.
하지만 이는 어디까지나 **저수준 데이터 접근 메커니즘의 문제**이지, 업무 규칙은 아님.

중요한 건 **데이터 구조와 데이터 모델**.
데이터 자체와 데이터를 어떻게 구조화할지는 아키텍처에서 중요함.

하지만 그 데이터를 MySQL, PostgreSQL, Oracle 같은 어떤 DB에 저장할지는 세부사항.

**데이터는 중요하다. 데이터 모델도 중요하다.
하지만 DB는 세부사항이다.**
