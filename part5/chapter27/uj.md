# Clean Architecture 5부 27장: '크고 작은 모든' 서비스들

서비스 지향 아키텍처 : 서비스 수준에서 경계를 나눈 아키텍처를 말하는 것인가

=> 요즘 좋다고 많이 채택을 하는데 사실 무조건 좋은 건 아니다

서비스와 횡단 관심사
횡단 관심사(cross-cutting concern). 단일한 영역에서만이 아니라 여러 영역에 걸쳐 고려해야하는 여건.

=> 즉, 하나의 관심사가 여러 서비스에 걸쳐 있는 경우가 있음.

---

개선책 : 컴포넌트 기반 서비스
횡단 관심사의 경우, 각 서비스 코드를 다 건드리는 게 아니라, 별도의 컴포넌트로 분리해서 관리.

분리된 서비스에서도 내부적으로 다수의 컴포넌트로 분리할 수 있음.

---

그래서 서비스 수준에서의 경계보다,
내부든 외부든 그어진 경계를 기준으로 경계에서의 "의존성 방향"을 통제하는 게 더 "시스템 아키텍처"에서 중요한 요소이고, 더 클린아키텍처다움.
