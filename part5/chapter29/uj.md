# Clean Architecture 5부 29장: 클린 임베디드 아키텍처

하드웨어, 펌웨어의 발전속도에 맞춰, 소프트웨어의 코드도 덩달아 수정이 되어야 하지만. 관계가 있다고 해서 의존성이 높으면 안 된다. 소프트웨어와 펌웨어의 경계/분리가 중요.

---

깔끔한 임베디드 소프트웨어 아키텍처와 코드 유효 수명 연장을 위한 방향성

- 앱티튜드 테스트 : 우선동작, 빠르게 개발에만 초점을 맞추고, 올바르게 리팩토링하는 일은 뒷전.

- 타깃하드웨어 병목현상 : 특정 하드웨어에서만 테스트가 가능하여 진척이 느려지는 현상

- 계층의 혼란 : 소프트웨어 / 펌웨어 / 하드웨어 이어야 하는데, 펌웨어 / 하드웨어로 하드웨어에 맞춰 소프트웨어 개발을 진행하는 경우 걍 다 펌웨어 개발이 되어버림  
  => 해결책 : HAL(소프트웨어-펌웨어 경계, 하드웨어 추상화 계층)을 분명하게 함.
- HAL은 타깃 하드웨어에 상관없이 테스트를 할 수 있는 경계층, 하드웨어를 추상화해서 소프트웨어가 특정 보드나 칩에 직접 묶이지 않게 만들어줌.
- 임베디드 소프트웨어와 펌웨어가 stdint.h를 사용하도록 만듦(하드웨어나 컴파일러마다 달라질 수 있는 타입 크기 문제를 줄여줌)
- 운영체제 추가 -> 소프트웨어 / OS / 펌웨어 / 하드웨어
  -> OSAL(소프트웨어-운영체제 경계, 운영체제 추상화 계층)

---

결론적으로, 임베디드라고 해서 소프트웨어가 하드웨어에 직접 묶이면 안 된다.
하드웨어, 펌웨어, OS는 세부사항.
**그러므로, 임베디드에서 클린아키텍처는 서로 계층 간 경계를 명확히 하고, HAL, OSAL 에서 시행하는 테스트는 하드웨어나 운영체제에 종속적이지 않게 하는 것**
