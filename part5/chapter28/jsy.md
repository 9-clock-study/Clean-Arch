# 테스트 경계

## 테스트를 고려한 설계

- 테스트가 시스템의 설게와 잘 통합되지 않으면, 테스트는 깨지기 쉬워지고, 시스템은 변경하기 어려워진다.
- 시스템의 공통 컴포넌트가 변경되면 수백 심지어 수천 개의 테스트가 망가진다.

- 소프트웨어 설계의 첫번 째 규칙 : 변동성이 있는 것에 의존하지 말것

업무 규칙을 테스트 할 수 있도록 할 것 <- ## 테스트 API

## 테스트 API

위에서 말한 업무 규칙을 테스트할 수 있도록.. 에는 이러한 특화 API를 만들면 된다.

- 테스트 API는 테스트를 애플리케이션으로부터 분리할 목적으로 사용한다.
