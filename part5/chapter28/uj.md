# Clean Architecture 5부 28장: 테스트 경계

- 테스트는 태생적으로 의존성 규칙을 따름
- 의존성은 항상 테스트 대상이 되는 코드를 향함
- 테스트(바깥)는 시스템의 컴포넌트(안쪽)을 향함
- 테스트는 독립적으로 배포 가능
- 시스템 운영에 필요하진 않으므로, 가장 고립되어 있음.

---

Test Driven 설계

1. 중요한 이유

- 시스템과 결합이 강한 경우, 시스템의 간단한 변경사항이 테스트 슈트를 다 망가뜨릴 수 있음 => 대량의 테스트 실패

2. 세부사항에 의존하지 않는 테스트 설계

- 변동성이 큰 부분에 의존하는 테스트는 망가지기 쉬움.

=> 모든 업무규칙 검증에 적용 가능한 "TEST API"

- 테스트구조를 애플리케이션 구조로부터 분리(결합 분리)
