경계의 다양한 형태 알아보기

# 경계 횡단하기

"런타임에 경계를 횡단한다" : 그저 경계 한쪽에 있는 기능에서 반대편 기능을 호출해 데이터를 전달하는 일에 불과
적절한 위치에서 경계를 횡단하는 비결은 **소스 코드 의존성 관리에 있음**

# 두려운 단일체 - 구분되지 않은 형태

- 함수와 데이터가 단일 프로세서에서 같은 주소 공간을 공유하며 나름의 규칙에 따라 분리되어 있을 뿐(소스 수준 분리 모드)

- 배포관점에서는 실행가능한 jar 파일로 묶인 일련의 자바 클래스 파일, EXE파일로 묶인 .NET 바이너리 등
  -> 이처럼 단일체는 경계가 드러나지 않음

- 가장 단순한 형태의 경계 횡단은 저수준 클라이언트에서 고수준 서비스로 향하는 함수 호출(p187 그림 18.1)

- 고수준 클라이언트가 저수준 서비스를 호출해야 한다면 동적 다형성을 사용해 제어흐름과 반대 방향으로 의존성을 역전시킬 수 있다.

- 단일체에서는 컴포넌트 간 통신은 매우 빠르고 값싸다. 통신은 전형적인 함수 호출에 지나지 않는다.

# 배포형 컴포넌트

- 동적 링크 라이브러리 형태 (배포 수준 결합 분리 모드)

- 컴포넌트를 분리하거나 컴포넌트 간 의존성을 관리하는 전략도 단일체와 동일

  > 큰 덩어리에서 적당히 큰 덩어리로 나눈것

# 스레드

- 스레드는 실행 계획과 순서를 체계화하는 방법에 가까움

# 로컬 프로세스

- 위 두 형태보다 강한 물리적 형태

- 주로 명령행이나 그와 유사한 시스템 호출을 통해 생성

- 동일한 프로세서 또는 하나의 멀티코어 시스템에 속한 여러 프로세서들에서 실행되지만, 각각 독립된 주소 공간에서 실행

- 소켓, 메일박스, 메시지 큐와 같은 운영체제에서 제공하는 통신 기능을 이용하여 서로 통신

- 로컬 프로세스는 컴포넌트 간 의존성을 동적 다형성을 통해 관리하는 저수준 컴포넌트로 구성

- 분리 전략은 단일체나 바이너리 컴포넌트의 경우와 동일

- 저수준 프로세스가 고수준 프로세스의 플러그인이 되도록하자

- 운영체제 호출, 데이터 마샬링/언마샬링, 문맥교환 등 제법 비싼 작업 (너무 빈번한 호출은 X)

# 서비스

- 가장 강력한 경계

- 서비스들은 모든 통신이 네트워크를 통해 이뤄진다고 가정

- 서비스 경계를 지나는 함수 호출에 비해 느림 (이 수준의 통신에서는 지연에 따른 문제를 고수준에서 처리할 수 있어야 함)

- 이를 제외하고는 로컬 프로세스에 적용한 규칙이 그대로 적용
