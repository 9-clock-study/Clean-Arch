# Clean Architecture 5부 19장 정리: 정책과 수준

> 좋은 아키텍처 => 동일한 이유로 함께 변경되는 정책을 같은 수준에 모으고, 의존성이 저수준에서 고수준으로 향하도록 배치하는 구조.

---

## 1. 정책이란 무엇인가

정책 : 시스템이 따라야 하는 규칙

```text
정책
→ 시스템이 어떤 판단을 하고
→ 어떤 절차를 따르며
→ 어떤 규칙에 따라 동작해야 하는지를 정한 것
```

입력 처리 방식, 출력 형식, 데이터 저장 방식도 넓은 의미에서는 정책이 될 수 있음.
그런데 모든 정책의 수준이 같은 것은 아님.

```text
고수준 정책
→ 시스템의 핵심 업무 규칙
→ 입출력 방식과 멀리 떨어져 있음
→ 쉽게 바뀌면 안 되는 중심 규칙

저수준 정책
→ 입출력, DB, UI, 프레임워크, 장치와 가까운 규칙
→ 세부사항에 가까움
→ 상대적으로 자주 바뀜(변경 가능성 높음)
```

---

## 2. 수준이란 무엇인가

```text
수준
→ 입력과 출력으로부터 얼마나 멀리 떨어져 있는가
```

입출력에서 멀리 있을수록 고수준.  
입출력에 가까울수록 저수준.

```text
고수준
┌──────────────────────────┐
│ 핵심 업무 규칙            │
│ 중요한 정책               │
└──────────────────────────┘
            ↑
            │
┌──────────────────────────┐
│ 유스케이스 정책           │
│ 업무 절차                 │
└──────────────────────────┘
            ↑
            │
┌──────────────────────────┐
│ 인터페이스 어댑터         │
│ 데이터 변환, 화면/DB 연결 │
└──────────────────────────┘
            ↑
            │
┌──────────────────────────┐
│ 입출력 장치, DB, UI, 웹   │
│ 프레임워크, 외부 시스템   │
└──────────────────────────┘
저수준
```

=> 수준은 'more/less important'를 떠나서, **입력과 출력이라는 세부사항에서 얼마나 떨어져 있는지**를 기준으로 판단

---

## 3. 고수준 정책과 저수준 정책

고수준 정책 : 시스템의 본질에 가까운 규칙

```text
고수준 정책
→ 업무 규칙
→ 유스케이스
→ 핵심 판단 기준
→ 시스템의 목적과 직접 연결되는 규칙
```

저수준 정책 : 세부사항에 가까운 규칙

```text
저수준 정책
→ 화면 표시 방식
→ DB 저장 방식
→ 외부 API 호출 방식
→ 파일 입출력 방식
→ 네트워크 통신 방식
```

```text
고수준 정책
→ 어떤 조건에서 주문이 승인되는가

저수준 정책
→ 승인된 주문을 어떤 DB 테이블에 저장할 것인가
→ 승인 결과를 어떤 JSON 형식으로 반환할 것인가
→ 화면에 어떤 버튼으로 보여줄 것인가
```

## 4. 정책과 수준에 대한 도식화

```text
높은 수준 / 안정적 / 추상적
┌──────────────────────────────┐
│ 핵심 업무 규칙                 │
│ - 가장 중요한 정책             │
│ - 입출력에서 가장 멀다          │
│ - 안정적이어야 함              │
│ - 추상적이어야 함              │
└──────────────────────────────┘
              ↑ 의존성 방향
              │
┌──────────────────────────────┐
│ 유스케이스 정책                │
│ - 업무 절차                    │
│ - 시스템이 수행해야 하는 흐름   │
└──────────────────────────────┘
              ↑ 의존성 방향
              │
┌──────────────────────────────┐
│ 인터페이스 어댑터              │
│ - 데이터 변환                  │
│ - 화면/DB/API 연결             │
└──────────────────────────────┘
              ↑ 의존성 방향
              │
┌──────────────────────────────┐
│ 입출력, DB, UI, 프레임워크      │
│ - 세부사항                     │
│ - 입출력에 가장 가까움          │
│ - 바뀔 가능성이 큼             │
└──────────────────────────────┘
낮은 수준 / 불안정 / 구체적
```

```text
의존성 방향
→ 저수준에서 고수준으로 향해야 함

변경 방향
→ 저수준 세부사항의 변경이 고수준 정책으로 전파되면 안 됨
```

---

# 정리

정책을 수준에 따라 배치하고,  
의존성 방향이 그 수준을 반영하도록 만들어야 한다.

```text
수준
→ 입력과 출력까지의 거리

입출력에서 멀수록
→ 고수준

입출력에 가까울수록
→ 저수준

동일한 이유로 동일한 시점에 변경되는 정책
→ 동일한 수준
→ 동일한 컴포넌트에 위치

서로 다른 이유로 다른 시점에 변경되는 정책
→ 다른 수준
→ 다른 컴포넌트로 분리

좋은 아키텍처
→ 컴포넌트를 연결할 때 의존성 방향에 컴포넌트의 수준이 반영되어야 함

의존성 방향
→ 저수준에서 고수준으로 향해야 함
```

| 원칙 | 역할                                                  |
| ---- | ----------------------------------------------------- |
| SRP  | 서로 다른 변경 이유를 가진 정책을 분리                |
| CCP  | 같은 이유로 함께 변경되는 정책을 같은 컴포넌트에 배치 |
| OCP  | 고수준 정책을 저수준 세부사항 변경으로부터 보호       |
| DIP  | 의존성 방향을 저수준에서 고수준으로 역전              |
| SDP  | 더 안정적인 고수준 정책 쪽으로 의존성 배치            |
| SAP  | 안정적인 고수준 정책을 추상적으로 유지                |
